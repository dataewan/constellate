# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status: Phases 1–4 implemented (Phase 4 minus cross-platform testing)

Phases 1–4 are built and working; only Phase 5 (optional web enrichment) and cross-platform (Linux/Windows) verification remain. What exists today: CLI (`--vault`, `--db`, `--ref-format`, `--no-embed`, `--embed-backend`, `--embed-model`, `--ollama-url`, `--llm-provider`, `--llm-model`), recursive Markdown scanner (excludes `.constellate/` and hidden dirs), a frontmatter / link / tag / heading-chunk parser, SQLite index with incremental content-hashing, a synchronous ratatui 4-pane TUI (files list + search, read-only preview, related-notes, and a persisted scratchpad), the cheap related-notes engine (`related.rs`), **semantic embeddings** (`embed/`, computed on a background worker thread, `worker.rs`) with brute-force cosine similarity **merged into** the related-notes list, **two embedding backends** behind an `Embedder` trait — Ollama (default) and a feature-gated in-process `fastembed`/ONNX backend — **clipboard yank** via `arboard`, `$EDITOR` suspend/restore, a debounced `notify` watcher, and a file logger (`logging.rs`). `cargo test` covers parsing, the store round-trip, relatedness, merge, semantic similarity, markdown/code rendering, link insertion, and the synthesis slug/date helpers (29 tests). The rest of this file still describes the full intended design from `plan.md`; treat anything beyond the above as not-yet-built.

> **Dependency note:** `rusqlite` is pinned to `0.37` on purpose — 0.38+ pulls `libsqlite3-sys` ≥0.38, whose build script uses the still-unstable `cfg_select!` and won't compile on the current toolchain. Don't bump it without re-checking that.

## What this is

`constellate` is a terminal-native knowledge-discovery tool in **Rust**. It indexes a local Markdown vault, computes vector embeddings locally, finds semantically similar notes as you navigate, and enriches the active note with Wikipedia/web lookups — all inside a `ratatui` TUI. The three journeys the design optimizes for: **browse & search** the vault, **edit** notes by handing off to `$EDITOR`, and **discover & reference** related notes (including yanking a note reference to the system clipboard).

Constellate is **not** a text editor — editing is delegated to the user's `$EDITOR`. A single static binary is a nice-to-have, not a hard requirement.

## Planned architecture

A **synchronous** ratatui render loop plus a background worker thread; slow work reports back over a channel (see `plan.md` for the full diagram and phased roadmap). Deliberately **no `tokio`** and **no `sqlite-vec`** — concurrency is a worker thread, and brute-force cosine in Rust is fast enough at personal-vault scale.

- **Vault Engine** — `walkdir` discovers `.md` files (excluding the `.constellate/` state dir); `pulldown-cmark` parses frontmatter, links, tags, and headings, splitting documents into heading-grouped chunks; `notify` + `notify-debouncer-full` coalesces save events and re-indexes only affected notes. **Inter-note links are standard Markdown links `[text](path)`** (the favoured style); `[[wikilinks]]` are still recognized for robustness. Link targets resolve to notes by filename stem / title in `related.rs`.
- **Related Notes Engine** — layered, cheapest first: shared inter-note links (Markdown `[](path)`), tag overlap, title/keyword overlap, then (Phase 3+) semantic cosine similarity merged into the same ranked list. Useful from Phase 2 without any model.
- **Storage** — `<vault>/.constellate/index.db` via `rusqlite` (bundled). Tables: `notes`, `chunks` (with `content_hash`), `links`, `tags`, `embeddings` (chunk_id, `f32` BLOB), `meta` (active backend/model/dimension → rebuild on mismatch).
- **Vector Search (`embed/`, implemented)** — pluggable `Embedder` trait: `OllamaEmbedder` (**primary**, `reqwest` blocking to a local Ollama server, default `nomic-embed-text`). Chunk vectors are stored as BLOBs; `SemanticIndex` aggregates them to a normalized per-note mean vector and does brute-force cosine in Rust, above a similarity threshold. Results are scaled and **merged** into the cheap related list via `related::merge`. Cached embeddings power semantic search even with `--no-embed` (offline); the `meta.embed_model` row gates a rebuild when the model changes. A second backend, in-process `FastEmbedder` (`embed/fastembed.rs`, ONNX `all-MiniLM-L6-v2`, 384-dim), is compiled only under `--features fastembed` and selected with `--embed-backend fastembed`; its `model_id` is `fastembed:all-MiniLM-L6-v2` so switching backends re-embeds. `Backend` (in `embed/mod.rs`) chooses/constructs the embedder in the worker thread; selecting `fastembed` without the feature errors at startup. (`fastembed`'s `TextEmbedding::embed` takes `&mut self`, so `FastEmbedder` wraps it in a `Mutex` to satisfy the `&self` trait method.)
  - **Embedding robustness (learned the hard way):** embedding models have a fixed context window (nomic-embed-text = 2048 tokens); over-long input returns HTTP 500. `OllamaEmbedder` truncates input to `MAX_INPUT_CHARS` (4000) to stay under it. Failures are classified via `EmbedError`: `Unreachable` (backend down → stop this session, show "unavailable") vs `Skip` (one bad input → log it and continue). **The worker must never abort the whole batch on a single chunk failure** — that was the original bug. Skips/failures are written to `<vault>/.constellate/constellate.log` (there is no stderr logging while the TUI owns the terminal).
- **Editor Integration** — `e`/`Enter` suspends the TUI (leave alternate screen, disable raw mode), spawns `$EDITOR` as a foreground child via `std::process::Command`, then restores the TUI and re-indexes the edited file on exit.
- **TUI** — `ratatui` + `crossterm` 3-column layout, with the **center column split** into preview (top) and scratchpad (bottom). Left column is pane 1 (`render_notes_list`): the notes list by **filename** (vault-relative, extension stripped, via `visible_files`). Center-top is the **read-only** note renderer (pane 2); center-bottom is the **scratchpad** (pane 4); right is the related-notes inspector (pane 3).
- **Scratchpad** (pane 4, `render_scratchpad`) — two columns: a **file list** (left, by filename via `display_filename`, never the derived title) and a **Commands menu** (right, `render_scratchpad_commands`) showing `(l) Link notes` and `(s) Send to LLM`. `a` adds the active note (dedup), `x` removes the highlighted entry (when pane 4 focused).
- **Linking** (`l`, `linking.rs`) — walks the not-yet-linked pairs of scratchpad notes (`RelatedIndex::are_linked` skips any pair already linked in either direction) and shows a modal (`render_link_modal`, an overlay via `Clear`) offering `[1] A→B / [2] B→A / [3] both / [4] skip / [Esc] cancel`. A link is a Markdown `[Title](path)` **appended at the end** of the source file, the path **relative to the source file's directory** (`<>`-wrapped if it has spaces). Modified files are re-indexed via `Action::ReindexPaths`.
- **Renaming** (`r`, `rename.rs`) — renames the active note's **slug** while keeping its `YYYYMMDDHHMM-` timestamp prefix. Only timestamped Zettel notes are renameable (`rename::is_renameable`; free-form filenames are rejected with a status message). A modal (`render_rename_modal`) shows the fixed prefix and an editable slug buffer prefilled with the current slug; `Enter` confirms, `Esc` cancels. On confirm, `Action::RenameNote { path, new_slug }` is handled in `run()`: the typed text is slugified (`rename::slugify`, mirroring `llm::slugify`), then inbound references are rewritten across the vault — Markdown-link destinations `](path)`/`](<path>)` whose final component names the old file get their filename swapped (directory prefix preserved, `<>`-rewrapped as needed), and `[[wikilink]]` targets matching the old stem are updated (aliases preserved) — before `fs::rename` moves the file. The old path (now vanished), new path, and every rewritten source are re-indexed via `sync_paths` (which deletes the gone note and inserts the new one); the scratchpad/related-basis are retargeted (`App::note_renamed`), the scratchpad persisted, and the notes list follows the note to its new name (`App::focus_path`). Renames refuse to clobber an existing target and leave the old file in place on any failure.
- **LLM configuration** (`c`, config modal + `llm/mod.rs`) — a `render_config_modal` overlay to choose the synthesis backend without leaving the TUI. Rows: **Provider** (←/→ cycles `ollama` → `claude` → `gemini`), **Model** (Enter → text-input, per-provider so switching backends remembers each one's model), and a **Prompts** row (inert in Phase 1 — Phase 2 wires the DB-backed prompt library). Config is stored in the SQLite `meta` table (`llm_provider`, `llm_model_{ollama,claude,gemini}`) via `Store::set_llm_*`, persisted on every change (`Action::LlmConfigChanged`). Backends sit behind an `LlmProvider` trait (`llm/mod.rs`): `OllamaProvider` (local `/api/generate`), `ClaudeProvider` (Anthropic Messages API `POST /v1/messages`, key from `ANTHROPIC_API_KEY`), `GeminiProvider` (`generateContent`, key from `GEMINI_API_KEY`) — all raw `reqwest` blocking (no SDKs). **Hosted-provider API keys come from environment variables, never the DB** (the vault may be a git repo). `build_provider` constructs the chosen backend on the synthesis thread and errors clearly (surfaced on the status line) when a hosted key is missing. Config precedence is **CLI flag (`--llm-provider`/`--llm-model`) > stored DB value > built-in default** (`resolve_llm_config` in `main.rs`); the CLI model override applies to the active provider only. `ProviderKind::default_model()` seeds the defaults (`qwen2.5` / `claude-opus-4-8` / `gemini-2.5-flash`).
- **LLM synthesis** (`s`, `llm/mod.rs`) — a prompt-picker modal (`render_prompt_modal`) offers a preset library (`llm::PROMPTS`) plus a custom free-text entry. On choose, `Action::GenerateSynthesis` spawns a **one-off background thread** that reads the scratchpad notes, calls the **configured provider** (see LLM configuration above; 300s timeout) via `run_synthesis(&dyn LlmProvider, …)`, and writes a new note to the **vault root**: `#TODO`, then Markdown links to the source notes, then the model output. Filename is `YYYYMMDDHHMM-<prompt-slug>.md` (Zettelkasten-style, UTC, deduped). The result comes back over a channel (`synthesis` receiver in `run`); the new file is re-indexed and **added to the scratchpad** (`App::add_path_to_scratchpad`). One synthesis at a time. Stored in the SQLite `scratchpad` table (`note_path`, `position`) — standalone, **no FK to `notes`** so re-indexing (which deletes+reinserts a note row) doesn't drop entries; dangling entries are tolerated in display. Persisted on every change via `Action::ScratchpadChanged` → `store.save_scratchpad`. Search (`/`, `refilter`) is a case-insensitive substring match over the **filename, the derived title, and the note content**. While search is active the interface **accent flips cyan→yellow** (focused-pane border + a bold `SEARCH` footer) as a modal cue that keystrokes are going into the search box. (The derived `NoteRow.title` — frontmatter `title:` → first heading → filename — is still used for the center-pane title, sort order, and the link text of Markdown-link yanks.) The center pane renders **styled Markdown** (`ui/markdown.rs`): a hand-rolled `pulldown-cmark` → ratatui `Text` converter for structure (headings colored+bold, emphasis, inline code, list markers, block quotes, links), and **`syntect`** for per-language token highlighting inside fenced code blocks (bundled syntaxes, `base16-ocean.dark` theme, truecolor `Color::Rgb`; pure-Rust `fancy-regex` engine, no `onig` C dep; unknown languages fall back to a flat style). `syntect`'s default set is loaded once via a `OnceLock`, and the rendered preview is **cached on the `App`** (rebuilt only when the current note changes, not per frame). Panes have **focus** (`ui::Focus`): `1`/`2`/`3` jump directly, `Tab`/`Shift+Tab` cycle, and the focused pane's border is highlighted. `j`/`k` is context-sensitive per focus — select in Notes, **scroll** in Preview, select in Related. The view tracks three notes: the **anchor** (`App::anchor_note`, the Notes-pane selection); the **active note** (`App::active_note`, what the center pane previews and what edit/yank act on — the highlighted note while the Related or Scratchpad pane has focus, else the anchor); and the **related basis** (`related_basis` / `note_of_interest`, the note the related list is computed from — the scratchpad highlight while pane 4 has focus, else the anchor; the Related pane's own highlight never drives its list). So navigating the **Scratchpad** (pane 4) updates both the preview and the related list; navigating the **Related** pane (pane 3) updates only the preview and leaves its list stable; neither moves the anchor. `Enter` in the Related pane **commits** the highlight as the new anchor (via `RelatedNote.path`). The rendered preview is cached and rebuilt on any active-note change (`rebuild_preview`). `y` yanks a note reference to the clipboard via `arboard`, formatted per `--ref-format`: **`markdown`** (default) → `[Title](relative/path.md)` (destination wrapped in `<>` when it contains spaces), `relative`, or `absolute`.
- **External Knowledge Engine (Phase 5, optional/experimental)** — key-noun extraction → Wikipedia REST summary on the worker thread. Off by default; may be cut.

Current module layout: `src/{main.rs, cli.rs, config.rs, vault/{mod,scanner,chunker}, db/{mod,store}, related.rs, rename.rs, embed/{mod,ollama,fastembed}, worker.rs, editor.rs, clipboard.rs, linking.rs, llm/{mod,ollama,claude,gemini}, logging.rs, ui/{mod,app,markdown}, watch.rs}`. `embed/fastembed.rs` compiles only under `--features fastembed`. Not yet present: `external/wikipedia.rs`.

## Key architectural constraints

- **Deliver use cases before ML.** Browsing, editing, and clipboard references (Phases 1–2) need no embeddings and are the shippable core. Embeddings *augment* an already-working tool; don't let them block it.
- **Local-first, not necessarily single-binary.** Core indexing/search must work without a network. Ollama and bundled native libs are acceptable runtime deps. The Ollama backend and web enrichment are the only network features and must stay optional.
- **Synchronous UI, work off-thread.** Keep the render loop synchronous and single-owner of the terminal; dispatch HTTP/embedding to the worker thread and receive results over a channel. Do **not** reintroduce `tokio`.
- **Related notes start cheap** — link graph + tags + keyword overlap before any embedding; semantic similarity is an additive layer.
- **Editing is delegated to `$EDITOR`** — the center pane is read-only and never needs a text-input mode. Don't build an in-app editor.
- **Incremental indexing** — per-chunk `content_hash` means filesystem/editor events re-embed only changed chunks, never a full rebuild.
- **Embedding backends must be interchangeable** behind the `Embedder` trait; switching backend/model changes vector dimension, so the `meta` table gates a rebuild.

## Commands

- `cargo build` / `cargo build --release` — build
- `cargo run -- --vault ~/Notes` — run the TUI against a vault (defaults to the current dir)
- `cargo run -- --vault ~/Notes --no-embed` — run without a backend (cheap relatedness + any cached embeddings)
- `cargo run -- --vault ~/Notes --embed-model nomic-embed-text --ollama-url http://localhost:11434` — Ollama backend options
- `cargo build --features fastembed` then `cargo run --features fastembed -- --vault ~/Notes --embed-backend fastembed` — in-process ONNX backend (no Ollama; downloads the model on first use)
- `cargo run -- --vault ~/Notes --llm-provider claude --llm-model claude-sonnet-5` — use a hosted synthesis backend (`ANTHROPIC_API_KEY` / `GEMINI_API_KEY` for `claude`/`gemini`); or set it in-app with `c`. Provider/model are persisted in the DB; CLI flags override for one run.
- `cargo test` — run all tests. Note: the `fastembed` code path is feature-gated, so also `cargo clippy --features fastembed` when touching `embed/`.
- `cargo test <name>` — run a single test by name substring
- `cargo clippy` — lint
- `cargo fmt` — format

The index lives at `<vault>/.constellate/index.db`. Inspect it with `sqlite3 <vault>/.constellate/index.db`. Background-worker events (embedding skips/failures) are logged to `<vault>/.constellate/constellate.log` — check there first when embeddings/related notes misbehave.

### Keybindings (in-app)

- `1`/`2`/`3`/`4` focus the Notes / Preview / Related / Scratchpad pane; `Tab`/`Shift+Tab` cycle panes (focused pane border is highlighted).
- `a` adds the active note to the scratchpad; `x` removes the highlighted scratchpad entry (when pane 4 is focused).
- `l` links the scratchpad notes: a modal steps through unlinked pairs (`1` A→B, `2` B→A, `3` both, `4` skip, `Esc` cancel), appending Markdown links to the files.
- `s` sends the scratchpad to the LLM: pick a preset prompt (`1`–`6`) or `Custom…`, and a new `#TODO` synthesis note is written to the vault root.
- `c` opens the LLM config modal: choose the provider (Ollama / Claude / Gemini) and per-provider model. Hosted keys come from `ANTHROPIC_API_KEY` / `GEMINI_API_KEY`.
- `j`/`k` or `↑`/`↓`: context-sensitive — select a note (Notes), scroll (Preview), or select a related note (Related).
- In the **Related** pane, `j`/`k` live-previews each related note in the center pane (Notes selection stays put); `Enter` commits the highlighted note as the new anchor.
- `Enter`: open the active note in `$EDITOR` (Notes/Preview) or **commit/jump** to the highlighted related note (Related).
- `e` open the current note in `$EDITOR`; `r` rename the active note (see below); `y` copy a reference to it (format set by `--ref-format`).
- `r` renames the active note's slug (timestamped Zettel notes only): a modal shows the fixed `YYYYMMDDHHMM-` prefix and an editable slug (prefilled with the current one); `Enter` confirms, `Esc` cancels. Inbound Markdown/wikilink references across the vault are rewritten before the file is moved (see the `rename.rs` note in the architecture section).
- `/` search; `Enter`/`Esc` leaves the search input keeping the filter, and a second `Esc` clears it; `q` quit.
